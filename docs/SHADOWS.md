## English

**Current main edition: WorldEntities2 Dynamic.** Blocks and entity models cast world shadows through the observed-geometry cache; `CHROMA_ENTITY_SHADOWS=1` is the default. Models receive Chroma light and world shadows. The accepted VacancyBounds1b path accelerates retained-geometry vacancy checks with conservative depth bounds. See [validation](SHADOW_VALIDATION.md). WorldEntities2 retains WorldEntities1/VacancyBounds1b shadow geometry, fixes ordinary wool being mistaken for a light marker, and makes added Chroma light independent of native ambient lighting. Static builds share the marker and lighting fixes; Static shadow geometry is unchanged. Legacy Auto remains on `codex/auto`.

**Select WorldEntities2:** enable **Chroma Shadows Dynamic WorldEntities2** (`Chroma-Shadows-Dynamic-26.3.zip`) at highest priority and disable the previous Chroma pack. **F3+T alone does not select a different ZIP.**

**Entity world shadows:** opaque/cutout models contribute observed surfaces to the same world cache as terrain. This includes mobs, players, armour stands and block-entity models such as chests, heads and shulker boxes. A cached caster may keep casting after leaving the camera view while it remains in the cache window. Unseen or hidden geometry is not supplied by the resource pack. This edition uses **mode `1`**, without a screen-shadow fallback. Translucent OIT-covered pixels retain the glass/water limitations below. Use **Improved Transparency ON**.

Enable **only one edition**, at highest resource-pack priority. Press **F3+T** after replacing it and after changing worlds or dimensions. Static must match its exported world and dimension; this reload does not update its baked geometry. Light commands remain the same: up to 128 sources, one `item_display` each, five reusable shapes, independent colour/brightness/radius/direction, no assigned source ID. Both shadow editions allow moving lights. See the [light commands](README.en.md).

The camera packet now uses the near depth plane, and all markers write identical camera data. Light discovery scans the full available packet area instead of choosing a scan bound by marker depth. Close terrain therefore cannot hide the camera packet, and the shadow editions no longer replace `terrain.fsh`. This removes the terrain-shader dependency that Sodium ignored. Vanilla block/water/fire screen effects also preserve the camera and source packets: otherwise entering a block can disable every light. Those perspective overlays have gaps at reserved packet cells; the ordinary orthographic GUI is unchanged. Entity tracking and renderer culling still apply; see the exact tested versions and cases in [validation](SHADOW_VALIDATION.md).

**Axiom display handles:** the centre cube and selected move/rotate/scale handles used by Axiom 6.1.2 are recognized by their local mesh, vertex colour and uniform scale, and marked as interface depth. They remain visible but cannot fill the light's voxel and black out Dynamic's shadow map. Their fragments also leave Chroma's transport pixels intact, so handles and rings can show horizontal gaps across the reserved packet area. Recognition does not depend on the camera distance, so Axiom's position interpolation and locked handle scale remain supported. This targets the known editor meshes; real blocks at the emitter are still shadow casters. An identical untextured debug mesh with the same colour and transform cannot be distinguished by a vanilla shader. If a future Axiom version changes that mesh, this compatibility hook will need updating.

**Sodium entity culling:** Sodium `0.9.3-alpha.1+mc26.3` can discard an `item_display` source before its shaders run, including markers with zero culling dimensions. A light can therefore disappear in some room/view directions or when its marker is outside the view. A resource pack cannot receive data from an entity the renderer did not draw; this limitation is separate from shadow filtering. For this case, disable Sodium entity culling: close Minecraft, set `performance.use_entity_culling` to `false` in `config/sodium-options.json`, and restart. This setting affects all entities; the pack does not edit it.

**Dynamic** records observed surfaces in a persistent world-coordinate cache: `256³` quarter-block cells cover a moving `64³`-block window. Each cell can hold **four finite surface planes**, rather than only a filled quarter-block cube. Each plane has an 8-bit octahedral normal, a 6-bit offset measured from a stable cell-centred anchor, and a `4 × 4` coverage mask on world-aligned axes with `1/16`-block patches. The mask describes observed coverage, including exposed cutout gaps; it is not a complete copy of a block model or its texture. Plane orientation and offset remain quantized.

**Current-frame normal cache:** Dynamic rebuilds a framebuffer-sized `surface_normal` pass immediately before `voxel_update`. It uses the same native-camera depth reconstruction and support flags, then stores the normal in 15+15-bit octahedral form with validity/support bits. The six axis directions are exact; other directions remain quantized. Acquisition and mask evidence reuse this cache; removal requires a full projected patch/plane or whole-cell vacancy proof. Every pixel is rewritten, including invalid pixels, so this adds no history or extra update delay. Static has no such pass. Its isolated performance contribution has not been measured; earlier Surface17 timings do not establish current hybrid performance.

Acquisition and vacancy checks for retained cells run in **eight phases**, using `(worldCellY ^ (worldCellZ >> 3)) mod 8` so neighboring X cells share a phase. The first occupancy LOD is persistent: groups untouched by the current phase are skipped, but the whole level is rebuilt when the cache window moves. Source distance maps refresh within eight frames, giving roughly **16 rendered frames** for newly observed geometry to propagate through both stages. Each map is a refreshed snapshot, not immediate knowledge of unseen or changed blocks. Acquisition and mask refinement share the supported native-depth normal; adjacent faces/patches cannot supply positive evidence. Unsupported coarse normals cannot create planes, but a coarse positive still triggers finer probes. Positive patch observations take priority. Clearing retained coverage requires the full projected patch footprint; mixed clear/unknown probes require the same proof. Fully unknown patches remain stored unless the whole cell is proved empty. Whole-plane proof is required to remove a retained plane or reuse its occupied slot. The cache also clears all retained planes when there is no coarse positive and every raster ray through the cell proves vacancy, resolving unsampled remnants after movement. Hidden, clipped or interface-covered evidence prevents this proof. The volume test retains its 1 mm far-boundary tolerance; submillimetre fragments there are not guaranteed protection.

If a fifth distinct plane has no safely reusable slot, the cell becomes a **solid quarter-block**. This overflow is latched until the whole cell is observed empty; it does not automatically disappear after a few frames. Moving-entity history can still accumulate inside occupied cells: the historical Surface17 move/rotate test reached 21 overflow cells among 58 occupied cells, while a fresh cache at the same rotated pose had 52 occupied cells and zero overflow. Full-footprint removal can cost more near the camera because it covers more pixels; phase counts are not wall-clock or FPS guarantees.

Previously observed blockers can remain effective outside the current view while inside the cache window. Unseen geometry, hidden surfaces and edits behind the camera remain unknown. Entity models use this cache too; an old shape can remain until sufficient empty-space evidence is visible again. The historical Surface17 persistent-cache cow test cleared the old region after movement and both regions after removal, following five observer views per change; this is not proof of invisible-geometry cleanup. Thin silhouettes may be missed during initial acquisition, and four planes with `1/16`-block masks cannot reproduce arbitrary geometry exactly. Removing all lamps preserves the cache; **F3+T** clears its history and should be used after changing worlds or dimensions.

**Static** reads exported block geometry directly. A blocker inside the exported bounds is available from the first frame, even behind the camera. Blocks and doors retain their saved state until re-exported; moving lights do not require re-export. The export uses native 26.3 occlusion/collision shapes on a quarter-block grid, including saved door orientations. Glass, water and leaves are excluded. Moving entities, custom resource-pack model geometry and texture cutout holes are not exported. Thin details may thicken to a quarter block. Inspect `docs/shadow-world.json` inside the Static ZIP for bounds and export limitations.

**Geometry maintenance:** one current-frame `256 × 256` depth-summary target conservatively bounds screen tiles. Vacancy checks skip a tile only when its depth bound proves that its valid observations lie beyond the retained surface/cell; uncertain tiles keep the native per-pixel checks. Unknown/interface pixels prevent a clear summary. The same observed-space and clipping restrictions remain, without expiring unseen geometry or lowering shadow sample counts. [Validation](SHADOW_VALIDATION.md) records measured performance and the limits of the quality controls.

**Dynamic shadow calculation:** each of the 128 sources has a cached `128 × 128` octahedral radial-depth map and a finite-surface atlas built by the existing producer. The blocker search estimates the angular filter width. At widths up to half a local map texel, the filter intersects one central ray with candidate finite geometry from the atlas. Between half and one local texel, it smoothly blends that result with PCSS; wider kernels use PCSS. The local angular texel width accounts for the octahedral projection. PCSS uses **16 disk taps**, each blending four depth comparisons against the receiving plane with a bounded quantization bias. The geometry cache, `shadow_surface` producer and geometry bindings remain part of Dynamic. Candidate coverage is finite: this is not a full trace through every cached surface. Map resolution, plane/mask quantization and bias can still miss thin blockers or introduce edge/self-shadow artifacts.

`CHROMA_SOURCE_SIZE` in `assets/chroma/shaders/include/shadow_config.glsl` keeps its default radius of `0.35` blocks; `CHROMA_SHADOW_SAMPLES=16` selects the default filter count. Samples are fixed, with no temporal noise. Map generation and filtering use the same origin rounded to `1/4096` block. A moved/new source or changed radius bypasses the normal eight-frame source refresh; rotation alone only changes the spotlight cone, so the omnidirectional map can be reused. The source-map mechanism supports moving lights; its current validation scope is recorded separately in the validation report. Rebuild/reload after editing settings.

**Static shadow calculation is unchanged:** the exported quarter-block occupancy and `shadow_filter_static.glsl` retain the previous PCSS-like blocker search and 16-ray filter. Its cached source maps are also `128 × 128`. A 17-sample blocker search estimates penumbra width; shared blocker cells and neighboring map samples guide intersections with occupied quarter-cell boundaries. Thin details absent from those candidates can be missed, and a sloped surface represented as quarter-block steps can shadow itself at grazing angles. The new four-plane Dynamic cache does not change Static's export precision or filter.

**Bright penumbrae:** each lamp's brightness response saturates before applying shadow visibility; RGB mixing retains the actual shadowed energy. Fully lit colours and brightness remain unchanged, while a small visible fraction no longer nearly saturates a bright lamp's penumbra. Coverage is still sampled: this reduces brightness jumps without increasing map resolution or adding temporal lag.

**Pixelated lighting and shadows are enabled by default in both shadow editions.** In `assets/chroma/shaders/include/shadow_config.glsl`, `CHROMA_SHADOW_PIXELATE=1` makes distance falloff, cone shape, surface-facing (Lambert) lighting and shadows use the same world grid; `0` restores continuous sampling for all of them. `CHROMA_SHADOW_PIXELS_PER_BLOCK` sets the positive integer number of subdivisions per block; its default `16` gives a `1/16`-block light/shadow pixel. This is independent of the quarter-block voxel geometry. Snapped samples stay on the receiving surface's plane, including slabs and sloped faces. Pixelation evaluates light and shadow at one world-grid position per surface pixel. Near a silhouette or another body part, that position can be shadowed while the visible fragment is lit; use `CHROMA_SHADOW_PIXELATE=0` for continuous sampling. The limit of four planes per cell, each with a 16-bit mask, still limits geometry and cutout accuracy; this is not a guarantee against self-shadow artifacts. Texture resolution is unchanged. After editing, rebuild the archive if working from source, replace the active pack and press **F3+T**.

**Sprite particles in Dynamic:** the default `CHROMA_PARTICLE_DEPTH_MASK=1` requires **Improved Transparency: ON**. Sprite particles, including block debris, smoke and dust, retain native colour and visibility tests while their covered pixels are excluded from voxel observations; geometry behind them remains unknown. Before using **Improved Transparency: OFF**, set `CHROMA_PARTICLE_DEPTH_MASK=0`, rebuild/replace the pack and press **F3+T**. This preserves classic particle rendering, but sprite particles can then cast shadows again. The 3D item-pickup animation and elder-guardian apparition use ordinary entity/item rendering and are not covered by this mask; they can still enter Dynamic's cache. Static never exports particles, and this shader override is disabled in Static.

**Glass and water in Dynamic:** the default `CHROMA_TRANSPARENT_DEPTH_MASK=1` also requires **Improved Transparency: ON**. Visible glass, stained-glass and water fragments in the OIT path neither cast nor receive Chroma light/shadows; their native colour remains visible. Fully transparent (`alpha = 0`) texture holes preserve the background depth and its Chroma lighting. A covered transparent pixel cannot provide the separate opaque-background depth to this RP: the background seen through tinted glass or water therefore remains **vanilla-lit**, without Chroma lighting at that pixel. This is an explicit limitation, not precise light transmission through the material. Before using **Improved Transparency: OFF**, set both `CHROMA_TRANSPARENT_DEPTH_MASK=0` and `CHROMA_PARTICLE_DEPTH_MASK=0`, rebuild/replace and press **F3+T**. With the transparent mask disabled, native transparent depth can again enter the receiver/caster path. Static keeps its existing behavior.

**What is shadowed:** direct light on world surfaces, weighted by the surface facing the source. Back-facing surfaces receive no direct light. The unshadowed analytic glow has been removed from both shadow editions because it illuminated rooms through opaque walls. First-person hands/held items and the separate 3D-HUD retain vanilla colour: only their actual covered pixels are excluded from Chroma light/fog/shadows and from voxel observations, so they do not become world occluders. World pixels around them are still processed; no fixed screen rectangle is masked. The ordinary 2D GUI is unchanged.

Playing requires only the RP and vanilla commands: no extra Java helper, mod or required datapack. Exporting Static is an authoring step using Python with NumPy, Pillow and nbtlib, plus the installed Minecraft 26.3 Java/runtime libraries. Save and close the world before exporting. Use the shared commands below from the project directory; optional `--min X Y Z --max X Y Z` limits the export, with maximum bounds exclusive.

## Русский

**Текущая основная версия: WorldEntities2 Dynamic.** Блоки и модели сущностей отбрасывают мировые тени через кеш увиденной геометрии; стандартный режим — `CHROMA_ENTITY_SHADOWS=1`. Модели получают свет Chroma и тени мира. Принятый вариант VacancyBounds1b ускоряет проверку пустоты сохранённой геометрии с помощью консервативных границ глубины. См. [проверки](SHADOW_VALIDATION.md). WorldEntities2 сохраняет геометрию теней WorldEntities1/VacancyBounds1b, устраняет ошибочное распознавание обычной шерсти как маркера и делает добавляемый свет Chroma независимым от штатного фонового освещения. Сборки Static получают те же исправления маркеров и света; геометрия теней Static не изменена. Прежний Auto сохранён в `codex/auto`.

**Выбор WorldEntities2:** включите **Chroma Shadows Dynamic WorldEntities2** (`Chroma-Shadows-Dynamic-26.3.zip`) с наивысшим приоритетом и отключите прежний Chroma. **Одного F3+T недостаточно для выбора другого ZIP.**

**Мировые тени сущностей:** непрозрачные модели и модели с вырезами добавляют увиденные поверхности в тот же мировой кеш, что и блоки. Это мобы, игроки, стойки для брони и модели блоков-сущностей, например сундуки, головы и шалкеровые ящики. Сохранённое препятствие может отбрасывать тень после выхода из кадра, пока остаётся в окне кеша. Невиденная и скрытая геометрия ресурспаку недоступна. Эта сборка использует **режим `1`**, без перехода к экранным теням. Пиксели под прозрачными OIT-материалами сохраняют ограничения стекла/воды ниже. Нужен **Improved Transparency ON**.

Включите **только один вариант** с наивысшим приоритетом. Нажмите **F3+T** после замены пака и после перехода в другой мир или измерение. Static должен соответствовать экспортированному миру и измерению; перечитывание пака само по себе не обновляет геометрию. Команды света прежние: до 128 источников, один `item_display` на источник, пять повторяемых форм, независимые цвет/яркость/радиус/направление, без назначения ID. Свет можно перемещать в обоих вариантах. См. [команды источников](README.ru.md).

Пакет камеры теперь записывается на ближней плоскости глубины, причём все маркеры передают одинаковые данные камеры. Поиск источников проходит всю доступную область пакетов, а не выбирает её границу по глубине маркера. Близкая геометрия больше не перекрывает пакет камеры; варианты с тенями больше не заменяют `terrain.fsh`, который Sodium игнорировал. Ванильные экранные эффекты блока/воды/огня также сохраняют пакеты камеры и источников: раньше попадание камеры в блок могло отключить весь свет. В этих перспективных наложениях появляются пропуски на служебных ячейках; обычный ортографический GUI не меняется. Передача сущностей клиенту и отсечение рендерером по-прежнему действуют; точные проверенные версии и случаи приведены в [отчёте](SHADOW_VALIDATION.md).

**Маркеры Axiom:** центральный куб и выделенные элементы перемещения, вращения и масштаба Axiom 6.1.2 распознаются по локальной геометрии, цвету вершин и равномерному масштабу. Они остаются видимыми, но не заполняют воксель лампы и не перекрывают её свет. Защита пикселей передачи данных может оставлять горизонтальные пропуски на осях и кольцах в области служебных пакетов. Распознавание не зависит от расстояния до камеры; реальный блок внутри источника продолжает отбрасывать тень. Шейдер не может отличить другую отладочную фигуру с полностью совпадающими геометрией, цветом и преобразованием. При изменении геометрии в будущих версиях Axiom потребуется обновить этот обработчик.

**Отсечение сущностей в Sodium:** Sodium `0.9.3-alpha.1+mc26.3` может исключить источник `item_display` ещё до запуска его шейдеров, в том числе маркер с нулевыми размерами отсечения. Поэтому свет может исчезать при некоторых направлениях взгляда в комнате или когда маркер находится вне экрана. Ресурспак не может получить данные сущности, которую рендерер не нарисовал; это ограничение не связано с фильтрацией теней. В таком случае отключите отсечение сущностей Sodium: закройте Minecraft, установите `performance.use_entity_culling` в `false` в `config/sodium-options.json` и запустите игру снова. Настройка действует на все сущности; пак её не меняет.

**Dynamic** сохраняет увиденные поверхности в постоянном кеше с координатами мира: `256³` ячеек по четверти блока покрывают перемещаемое окно `64³` блока. Каждая ячейка вмещает **четыре конечные плоскости поверхности**, а не только заполненный куб размером в четверть блока. У каждой плоскости есть 8-битная нормаль в октаэдрическом кодировании, 6-битное смещение относительно устойчивой опорной точки у центра ячейки и маска покрытия `4 × 4` по осям мира с участками размером `1/16` блока. Маска описывает увиденное покрытие, включая открывшиеся вырезы текстуры; это не полная копия модели блока или его текстуры. Направление и смещение плоскости остаются квантованными.

**Кеш нормалей текущего кадра:** Dynamic полностью обновляет `surface_normal` размером с кадр непосредственно перед `voxel_update`. Используются прежнее восстановление по штатной камере и глубине и признаки подтверждения; нормаль сохраняется в октаэдрическом формате 15+15 бит с признаками корректности и поддержки. Шесть осевых направлений передаются точно, остальные остаются квантованными. Сбор геометрии и проверка маски используют этот кеш; удаление требует полной проверки следа участка/плоскости либо пустоты всей ячейки. Перезаписываются все пиксели, включая некорректные, поэтому новой истории или дополнительной задержки обновления нет. В Static такого прохода нет. Отдельный вклад кеша в производительность не измерялся; прежние замеры Surface17 не подтверждают скорость текущего гибридного фильтра.

Сбор поверхностей и проверки освобождения сохранённых ячеек идут в **восемь фаз** по формуле `(worldCellY ^ (worldCellZ >> 3)) mod 8`, поэтому соседние ячейки по X обновляются вместе. Первый уровень LOD заполненности хранится между кадрами: группы, не затронутые текущей фазой, пропускаются, но при перемещении окна кеша весь уровень пересобирается. Карты расстояний источников обновляются в пределах восьми кадров: новая увиденная геометрия проходит оба этапа примерно за **16 отрисованных кадров**. Каждая карта хранит обновляемый снимок, а не мгновенное знание невиденных или изменённых блоков. Сбор плоскостей и уточнение маски используют подтверждённую штатную нормаль; соседние грани и участки не дают положительного подтверждения. Неподтверждённая нормаль крупной пробы не создаёт плоскость, но положительное попадание запускает мелкие пробы. Подтверждённые участки имеют приоритет. Удаление сохранённого покрытия требует полной проверки проецируемого следа участка, включая смесь пустых и неизвестных проб. Полностью неизвестные участки сохраняются, пока не доказана пустота всей ячейки. Для удаления сохранённой плоскости или повторного использования её слота требуется проверить весь её след. Кеш также удаляет все сохранённые плоскости, если крупная проба не дала попадания и каждый растровый луч через ячейку подтверждает пустоту: это устраняет остатки после движения, в которые не попали отдельные пробы. Скрытая, обрезанная или перекрытая интерфейсом область блокирует такое подтверждение. У объёмной проверки сохранён допуск 1 мм у дальней границы; защита субмиллиметровых фрагментов там не гарантируется.

Если для пятой отдельной плоскости нет безопасно освобождаемого слота, ячейка становится **сплошным кубом в четверть блока**. Переполнение сохраняется до наблюдения пустоты всей ячейки, а не исчезает автоматически через несколько кадров. История движущейся сущности может накапливаться внутри занятых ячеек: в прежнем Surface17 после последовательного перемещения и поворота переполнение получили 21 из 58 занятых ячеек, а свежий кеш в той же повёрнутой позе дал 52 занятые ячейки без переполнения. Проверки полного следа могут стоить дороже вблизи камеры, где охватывают больше пикселей; число фаз не гарантирует время в секундах или FPS.

Ранее увиденные препятствия могут отбрасывать тени вне текущего кадра, пока находятся в окне кеша. Невиденная геометрия, скрытые поверхности и изменения за камерой остаются неизвестными. Модели сущностей также используют этот кеш; старая форма способна сохраняться до достаточного подтверждения пустого пространства. В прежнем тесте Surface17 с постоянным кешем старая область коровы очистилась после перемещения, обе области — после удаления; после каждого изменения использовались пять ракурсов наблюдения. Это не подтверждает очистку невидимой геометрии. Тонкие силуэты могут быть пропущены при первоначальном сборе, а четыре плоскости с масками по `1/16` блока не воспроизводят произвольную геометрию точно. Удаление всех ламп сохраняет кеш; **F3+T** очищает историю и нужен после смены мира или измерения.

**Static** читает экспортированную геометрию блоков. Препятствия внутри границ экспорта доступны с первого кадра, включая объекты за камерой. Блоки и двери сохраняют записанное состояние до нового экспорта; для перемещения ламп экспорт не нужен. Используются штатные формы перекрытия/столкновения 26.3 на сетке в четверть блока, включая сохранённую ориентацию дверей. Стекло, вода и листва исключены. Движущиеся сущности, геометрия нестандартных моделей RP и отверстия в текстурах не экспортируются. Тонкие детали могут утолщаться до четверти блока. Границы и ограничения конкретного экспорта находятся в `docs/shadow-world.json` внутри Static ZIP.

**Обслуживание геометрии:** один буфер сводной глубины текущего кадра `256 × 256` консервативно ограничивает экранные тайлы. Проверка пустоты пропускает тайл только тогда, когда граница глубины доказывает, что его допустимые наблюдения лежат за сохранённой поверхностью/ячейкой; сомнительные тайлы проверяются прежними штатными пиксельными пробами. Неизвестные/интерфейсные пиксели запрещают такую сводную очистку. Сохраняются ограничения наблюдаемого пространства и отсечения; невиденная геометрия не удаляется по таймеру, число выборок теней не уменьшается. [Отчёт](SHADOW_VALIDATION.md) фиксирует замеры производительности и границы проверок качества.

**Расчёт теней Dynamic:** у каждого из 128 источников есть кешируемая октаэдрическая карта радиальной глубины `128 × 128` и атлас конечных поверхностей, построенные прежним проходом. Поиск препятствий оценивает угловую ширину фильтра. При ширине до половины локального текселя карты один центральный луч проверяется на пересечения с конечной геометрией кандидатов из атласа. Между половиной и одним локальным текселем результат плавно смешивается с PCSS; более широкое ядро использует PCSS. Локальная угловая ширина текселя учитывает октаэдрическую проекцию. PCSS использует **16 выборок диска**, каждая смешивает четыре сравнения глубины с плоскостью принимающей поверхности и ограниченным допуском квантования. Кеш геометрии, проход `shadow_surface` и привязки геометрии сохранены. Набор кандидатов конечен: это не полная трассировка всех сохранённых поверхностей. Разрешение карты, квантование плоскостей/масок и bias всё ещё могут пропускать тонкие препятствия и давать артефакты краёв/самозатенения.

`CHROMA_SOURCE_SIZE` в `assets/chroma/shaders/include/shadow_config.glsl` сохраняет стандартный радиус `0.35` блока; `CHROMA_SHADOW_SAMPLES=16` задаёт стандартное число выборок фильтра. Выборки постоянны, без временного шума. Построение карты и фильтр используют общую позицию с шагом `1/4096` блока. Новый/перемещённый источник или изменение радиуса обновляют карту, не ожидая обычного восьмикадрового цикла; один поворот меняет только конус прожектора, поэтому всенаправленную карту можно использовать повторно. Механизм карт поддерживает движущиеся источники; объём проверок текущей сборки отдельно указан в отчёте. После изменения настроек пересоберите и перечитайте пак.

**Расчёт теней Static не изменён:** экспорт заполненных ячеек в четверть блока и `shadow_filter_static.glsl` сохраняют прежний поиск препятствий по принципу PCSS и фильтр из 16 лучей. Кешируемые карты источников также имеют размер `128 × 128`. Поиск по 17 выборкам оценивает ширину полутени; общие ячейки препятствий и соседние выборки карты направляют пересечения с границами занятых ячеек. Тонкие детали, не попавшие в кандидаты, могут быть пропущены, а наклонная поверхность из ступеней по четверти блока может затенять сама себя при скользящем свете. Новый кеш Dynamic с четырьмя плоскостями не меняет точность экспорта и фильтр Static.

**Полутени ярких ламп:** отклик яркости каждой лампы ограничивается до применения видимости из теней; смешение RGB сохраняет фактическую энергию света с учётом затенения. Полностью освещённые цвета и яркость не меняются, но небольшая видимая доля больше не делает полутень яркой лампы почти полностью освещённой. Видимость по-прежнему оценивается по выборкам: это уменьшает скачки яркости без увеличения карт и временного сглаживания.

**Пиксельное освещение и тени включены по умолчанию в обоих вариантах с тенями.** В `assets/chroma/shaders/include/shadow_config.glsl` значение `CHROMA_SHADOW_PIXELATE=1` привязывает спад яркости с расстоянием, форму конуса, освещение по направлению поверхности (Ламберт) и тени к одной сетке мира; `0` возвращает непрерывную выборку для всех этих расчётов. `CHROMA_SHADOW_PIXELS_PER_BLOCK` задаёт положительное целое число делений на блок; стандартное значение `16` даёт пиксель света/тени размером `1/16` блока. Оно не меняет воксельную геометрию с шагом в четверть блока. Округлённая точка остаётся на плоскости принимающей свет поверхности, включая плиты и наклонные грани. Пикселизация рассчитывает свет и тень в одной точке мировой сетки на каждый пиксель поверхности. У силуэта или рядом с другой частью модели эта точка может оказаться в тени, хотя видимый фрагмент освещён; `CHROMA_SHADOW_PIXELATE=0` включает непрерывное семплирование. Ёмкость из четырёх плоскостей с 16-битными масками на ячейку по-прежнему ограничивает точность геометрии и вырезов текстуры; отсутствие артефактов самозатенения не гарантируется. Разрешение текстур не меняется. После правки исходников пересоберите архив, замените активный пак и нажмите **F3+T**.

**Частицы-спрайты в Dynamic:** стандартное значение `CHROMA_PARTICLE_DEPTH_MASK=1` требует **Improved Transparency: ON**. Частицы-спрайты, включая обломки блоков, дым и пыль, сохраняют штатный цвет и проверки видимости, но занятые ими пиксели исключаются из наблюдений воксельного кеша; геометрия за ними остаётся неизвестной. Перед использованием **Improved Transparency: OFF** установите `CHROMA_PARTICLE_DEPTH_MASK=0`, пересоберите/замените пак и нажмите **F3+T**. Это сохраняет правильную отрисовку классических частиц, но частицы-спрайты снова смогут отбрасывать тени. Трёхмерная анимация подбора предмета и видение древнего стража используют обычную отрисовку сущностей/предметов и не покрываются этой маской: они всё ещё могут попадать в кеш Dynamic. Static никогда не экспортирует частицы; в нём эта правка шейдера отключена.

**Стекло и вода в Dynamic:** стандартное значение `CHROMA_TRANSPARENT_DEPTH_MASK=1` также требует **Improved Transparency: ON**. Видимые фрагменты стекла, окрашенного стекла и воды в тракте OIT не отбрасывают тени и не получают свет/тени Chroma; их штатный цвет остаётся видимым. Полностью прозрачные отверстия текстуры (`alpha = 0`) сохраняют глубину фона и его освещение Chroma. В пикселе, покрытом прозрачным материалом, ресурспаку недоступна отдельная глубина непрозрачного фона: поэтому фон, видимый через окрашенное стекло или воду, остаётся **освещённым только средствами vanilla**, без освещения Chroma в этом пикселе. Это явное ограничение, а не точный расчёт прохождения света через материал. Перед включением **Improved Transparency: OFF** установите одновременно `CHROMA_TRANSPARENT_DEPTH_MASK=0` и `CHROMA_PARTICLE_DEPTH_MASK=0`, пересоберите/замените пак и нажмите **F3+T**. При отключённой маске штатная глубина прозрачных поверхностей снова может участвовать в приёме света и создании теней. Поведение Static сохранено.

**Что затеняется:** прямое освещение поверхностей мира с учётом их направления к источнику. Обратные стороны поверхностей не получают прямого света. Аналитическое свечение без проверки теней удалено из обоих вариантов с тенями: оно освещало комнаты сквозь непрозрачные стены. Руки/предметы от первого лица и отдельный 3D-HUD сохраняют обычный цвет: только занятые ими пиксели исключаются из света/тумана/теней Chroma и наблюдений воксельного кеша, поэтому они не становятся препятствиями мира. Окружающие пиксели мира продолжают обрабатываться; фиксированная область экрана не маскируется. Обычный двумерный интерфейс не меняется.

Для игры нужны только RP и обычные команды; дополнительные Java-модули, моды и обязательный датапак не нужны. Экспорт Static выполняется при подготовке пака через Python с NumPy, Pillow и nbtlib, а также установленную Java с библиотеками Minecraft 26.3. Перед экспортом сохраните и закройте мир. Команды ниже выполняются из папки проекта. Необязательные `--min X Y Z --max X Y Z` ограничивают область; верхняя граница не включается.
