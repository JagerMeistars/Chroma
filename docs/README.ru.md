# Chroma — автоматические источники света

Chroma добавляет цветные точечные источники, три варианта прожектора, полусферы вниз, мягкое свечение и сине-серый туман в **Minecraft Java 26.3**. Это обычный ресурспак формата **97.1**; обязательные моды и датапак не нужны. Теней от источников нет. Туман остаётся и тогда, когда источников света нет.

## Установка и первый источник

1. Поместите `Chroma-Auto-26.3.zip` или папку `Chroma` в `minecraft/resourcepacks`. Файлы `pack.mcmeta` и `assets` должны находиться в корне архива/папки.
2. Включите Chroma в **Настройки → Наборы ресурсов**. Используйте одну копию и сначала проверьте пак отдельно. Другие паки, заменяющие core-шейдеры или `minecraft:post_effect/end_of_frame.json`, требуют согласованного объединения файлов. RPDREVO не нужен.
3. После замены файлов нажмите **F3+T**. Используется механизм конца кадра из 26.3; старая схема установки через Fabulous для 26.2 здесь не применяется.
4. В мире с доступом к командам создайте источник над светлым полом:

```mcfunction
/summon minecraft:item_display ~ ~2 ~ {Tags:["chroma.demo","chroma.demo.warm"],billboard:"fixed",item_display:"none",view_range:4f,width:0f,height:0f,item:{id:"minecraft:paper",count:1,components:{"minecraft:item_model":"chroma:marker","minecraft:custom_model_data":{colors:[16759885]}}},transformation:{translation:[0f,0f,0f],left_rotation:[0f,0f,0f,1f],scale:[8f,0.3f,1f],right_rotation:[0f,0f,0f,1f]}}
```

Если команда не помещается в чат, используйте командный блок и уберите начальный `/`. Получится тёплый свет `#FFBC4D` с номинальным радиусом 8 блоков и яркостью `0.3`. Каждый игрок, которому нужен эффект, должен включить пак у себя.

**Повторно используйте `chroma:marker` для точечных источников в пределах бюджета 128 источников.** Выбирать и резервировать номер модели не нужно. На один источник нужна одна сущность `item_display`; внутри её модели находятся два технических четырёхугольника. Они передают данные шейдерам, а видимого корпуса лампы не рисуют. Декоративный блок или модель светильника можно поставить отдельно.

## Цвет, размер и форма

| Параметр | Назначение |
| --- | --- |
| `minecraft:custom_model_data.colors[0]` | Цвет RGB как число `R*65536 + G*256 + B`. Белый: `16777215`; красный: `16711680`; зелёный: `65280`; синий: `255`. По умолчанию белый. |
| `transformation.scale[0]` — X | Номинальный радиус в блоках; положительное число. |
| `transformation.scale[1]` — Y | Яркость. Начните с `0.1f`–`0.5f`; значение должно быть положительным. |
| `transformation.scale[2]` — Z | Оставьте `1f`. |
| `item_display:"none"`, `billboard:"fixed"` | Сохраните эти настройки для правильной геометрии и направления маркера. |

| Модель предмета | Форма света |
| --- | --- |
| `chroma:marker` | Точечный свет во все стороны. |
| `chroma:marker_spot_narrow` | Узкий прожектор, внешний полуугол около 16°. |
| `chroma:marker_spot` | Средний прожектор, внешний полуугол около 28°. |
| `chroma:marker_spot_wide` | Широкий прожектор, внешний полуугол около 42°. |
| `chroma:marker_dome` | Полусфера, направленная вниз по координатам мира. |

Одну и ту же модель можно использовать у нескольких источников, в том числе в одной точке. Цвет, позиция, радиус, яркость и направление настраиваются независимо. Прежние названия моделей с числовыми суффиксами оставлены только для совместимости: числа больше не выделяют слоты света.

Прожекторы следуют повороту дисплея. Значение `left_rotation:[0.7071068f,0f,0f,0.7071068f]` направляет прожектор вниз — это положительный поворот на 90° вокруг X. Отрицательная X-компонента направляет его вверх. Полусфера всегда смотрит вниз по миру, независимо от поворота дисплея. Свечение вокруг источника использует сферическое приближение для всех форм.

Все полусферы слегка мерцают. Фаза зависит от цвета и не меняется из-за порядка автоматического сбора. Точечные источники и прожекторы светят ровно. Чтобы убрать мерцание, установите `CHROMA_FLICKER_AMOUNT` в `0.0` в `assets/chroma/shaders/include/flicker.glsl` и перезагрузите пак.

## Изменение и удаление

Команды ниже выбирают ближайший тёплый источник из примера. Теги нужны только для командных селекторов; это не идентификаторы света. Используйте удобные теги для своей сцены.

```mcfunction
# Голубой цвет
/data modify entity @e[type=minecraft:item_display,tag=chroma.demo.warm,sort=nearest,limit=1] item.components."minecraft:custom_model_data".colors set value [6737151]
# Радиус и яркость
/data modify entity @e[type=minecraft:item_display,tag=chroma.demo.warm,sort=nearest,limit=1] transformation.scale[0] set value 12f
/data modify entity @e[type=minecraft:item_display,tag=chroma.demo.warm,sort=nearest,limit=1] transformation.scale[1] set value 0.15f
# Другая форма
/data modify entity @e[type=minecraft:item_display,tag=chroma.demo.warm,sort=nearest,limit=1] item.components."minecraft:item_model" set value "chroma:marker_dome"
# Перенести над вашей позицией
/tp @e[type=minecraft:item_display,tag=chroma.demo.warm,sort=nearest,limit=1] ~ ~2 ~
# Удалить только источники примера в текущем измерении
/kill @e[type=minecraft:item_display,tag=chroma.demo]
```

После удаления сущности свет исчезает в кадре, до которого дошло это изменение. Новый рендерер не сохраняет старую лампу на дополнительные кадры. Оставляйте X/Y положительными; для выключения удаляйте сущность, а не сжимайте её модель в ноль.

В [examples.mcfunction](examples.mcfunction) собраны отдельные примеры создания, редактирования и удаления. Копируйте нужный раздел; обязательным датапаком этот файл не является. [examples-128.mcfunction](examples-128.mcfunction) создаёт сетку 16 × 8 с 128 цветами и всеми пятью формами, используя только пять повторяемых названий моделей. Выполните команды один раз из **одной позиции** над полом, без других активных источников Chroma. Удаление этой сетки:

```mcfunction
/kill @e[type=minecraft:item_display,tag=chroma.test128]
```

## Тестовый датапак на 128 источников

В сохранение `objCubed` добавлен датапак `datapacks/chroma_test_128`. Включи или перечитай Chroma клавишами **F3+T**, затем один раз выполни в мире `/reload` и вызови `/function chroma_test:spawn128`. Функция удалит только предыдущие тестовые лампы и создаст сетку 16 × 8 вокруг позиции вызова команды. Очистка: `/function chroma_test:clear128`.

## Как работает новый способ

Текстура маркера задаёт форму, а цвет предмета и преобразованная геометрия — остальные параметры света. Рендерер использует адрес вершин маркера в текущем кадре, записывает данные в разреженный каталог GPU, подсчитывает корректные записи и собирает из них компактный рабочий список до 128 источников. Пользователь не задаёт адреса. Случайного хеширования здесь нет; источникам разных цветов не требуется общий заранее выбранный слот.

Сетка `128 × 72` хранит источники, способные повлиять на каждый участок экрана. Для списка из 128 ламп каждый участок использует четыре 32-битные маски. Финальный проход обрабатывает только эти источники и рассчитывает освещение поверхности вместе со свечением за один обход. Матрицы камеры декодируются на вершинах экранного треугольника, а не заново для каждого пикселя. Каждый кадр использует свежие данные маркеров и камеры, без постоянного кеша источников.

## Ограничения и проверка проблем

- **Бюджет — 128 одновременно отрисовываемых источников.** Названия моделей можно повторять, но рабочий список конечен. При превышении 128 часть источников не попадёт в него; на конкретный порядок отбора рассчитывать не следует.
- **Сущности должны отрисовываться.** Загрузка чанков, передача сущностей сервером, дальность и отсечение рендерером по-прежнему действуют. Нулевые width/height и увеличенный view_range из примера помогают, но не передают шейдеру незагруженные сущности.
- **Света нет:** проверьте первую команду над светлым текстурированным полом, включив только Chroma. X/Y должны быть положительными. Бумага в руке/инвентаре — ожидаемая запасная модель, а не поставленный источник.
- **Свет проходит сквозь стены.** Проверки препятствий между источником и поверхностью и теней нет. Это визуальный эффект: уровень блочного света, появление мобов и другая игровая механика не меняются.
- **FPS зависит от перекрытия и разрешения.** Отбор по участкам особенно полезен для разнесённых ламп. Если все 128 влияют на один пиксель, для него обрабатываются все 128. Условия фактических замеров приведены в [проверках](VALIDATION.md); универсального обещания FPS нет.
- **Прозрачные поверхности и границы глубины** могут показывать приближения экранного эффекта. Туман регулируется `FOG_DENSITY`/`FOG_SKY`, свечение — `VOL_STRENGTH` в `assets/chroma/shaders/post/shade.fsh`.
- **У транспорта конечное пространство адресов.** Каталог рассчитан на 65 536 исходных адресов вершин, дополнительно ограниченных размером кадра. Это внутренняя граница передачи данных, а не номера, которые требуется назначать лампам. Очень маленькое разрешение или необычно тяжёлая видимая геометрия моделей могут её превысить. Прежнего требования высоты 576 пикселей больше нет; кадр 320 × 240 вмещает примерно 6240 исходных адресов. При достижении границы уменьшите сложность видимых моделей или увеличьте разрешение.
- **Ошибка перезагрузки/конфликт паков:** посмотрите `minecraft/logs/latest.log` и сначала проверьте Chroma отдельно. Совместимость с модами, меняющими рендеринг, проверяется отдельно.
